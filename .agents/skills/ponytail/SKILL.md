# Ponytail — 구현 단계용 최소 구현 스킬

이 스킬은 승인된 Exec Plan의 구현 단계에서만 활성화한다. 계획·검증·리뷰 단계에 계속 적용하지 않는다.
공통 구현 계약, 승인 범위, TDD, 보안, 접근성, 검증 규칙을 대체하거나 완화하지 않는다.

## 파일을 고치기 전에

- 요청과 변경 대상 코드를 읽는다.
- 변경이 도달해야 하는 호출자, 테스트, fixture, 설정, export를 확인한다.
- 사용자 데이터 노출·손실이나 기존 호출 중단 등 부작용을 살핀다. 승인 범위를 넘는 기능은 추가하지 않는다.

## 작동하는 가장 작은 완전한 변경

다음 순서에서 요구사항을 완전히 충족하는 첫 방법을 선택한다.

1. 이 변경이 정말 필요한가? 요청하지 않은 기능·옵션·유연성은 만들지 않는다.
2. 기존 코드베이스에 같은 기능·helper·패턴이 있는가? 있으면 주변 코드 방식으로 재사용한다.
3. 프로젝트 관례와 충돌하지 않는 표준 라이브러리 또는 플랫폼 기능으로 해결할 수 있는가?
4. 이미 설치된 의존성이 해결하는가? 몇 줄을 위해 새 의존성을 추가하지 않는다.
5. 읽기 쉬운 한 줄로 충분한가?
6. 그 다음에만 최소 구현을 작성한다.

필요한 호출부·테스트·fixture까지 완성한다. 불필요한 추상화·wrapper·변환·옵션·설정·향후 대비 코드를 추가하지 않는다.
기존 계층과 인터페이스를 유지하고, 같은 크기의 대안이면 경계 조건에서 올바른 쪽을 택한다.
코드를 이동·병합해도 오류 처리와 검증을 보존한다. 새 비자명 로직에는 작은 테스트나 assert 기반 자체 검사를 둔다.
신뢰 경계의 검증, 데이터 손실 방지 오류 처리, 보안, 접근성 및 사용자가 요청한 동작은 줄이지 않는다.

구현을 마칠 때 생략한 항목과 미확인 위험이 있으면 짧게 기록한다.

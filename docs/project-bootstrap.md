# 프로젝트 부트스트랩 — 문맥 설정 절차

이 문서는 프레임워크를 신규 또는 기존 프로젝트에 **처음 적용한 직후** 프로젝트 문맥을
완성하는 절차의 SSOT다. 일반 기능 작업마다 반복하지 않는다.

## 원칙

1. 먼저 소스·설정·테스트·기존 문서를 조사한다. 이미 알 수 있는 사실을 사용자에게 다시 묻지 않는다.
2. 목적, 사용자, 정책 결정처럼 분석으로 확정할 수 없는 정보만 질문한다.
3. 분석 사실과 사용자 답변을 구분해 기록한다. 추측을 프로젝트 사실로 쓰지 않는다.
4. 기존 `AGENTS.md`, `CLAUDE.md`, README, 설계 문서는 보존한다. 갱신이 필요하면 diff를 제안하고 승인 뒤 반영한다.
5. 문서에 적은 실행·검증 명령은 실제로 확인하기 전 확정 사실로 기록하지 않는다.

## 절차

1. 대상 지침 파일을 읽고 `scripts/analyze-project.sh --project-dir <대상>`을 실행한다.
2. `scripts/prepare-project-context.sh --project-dir <대상> --write`로 질문 초안을 만든다.
3. LLM은 초안을 바탕으로 필요한 질문만 사용자에게 한 번에 제시한다.
4. 답변을 받은 뒤 아래 산출물의 초안 또는 diff를 작성한다.
   - `ARCHITECTURE.md`: 스택, 모듈 경계, 실행 경로, 외부 의존성, 확인되지 않은 항목
   - `docs/design-docs/project-context.md`: 목적, 사용자, 핵심 흐름, 도메인 용어, 제외 범위
   - `docs/project-constitution.md`: 고위험 변경 경계·아키텍처 불변 조건·규제·인증·프라이버시·검증 수준·안티골
   - `.ai-dev-standard.env`와 검증 스크립트: 실제 명령은 승인·실행 확인 뒤에만 연결
5. 신규 파일 생성 또는 기존 파일 diff를 사용자에게 보여주고 승인을 받는다.
6. 승인 범위만 반영하고, `scripts/check-framework.sh --project-dir <대상>`으로 골격을 확인한다.

## 질문 기준

다음은 소스만으로 확정할 수 없을 때만 질문한다.

- 제품 목적, 주요 사용자, 첫 번째 핵심 사용자 흐름
- 도메인 용어와 정책·권한 결정
- 데이터 저장소, 인증, 외부 서비스의 사용 여부
- 아직 없는 기술 스택 또는 배포 방식의 선택
- 브라우저 실측, 통합·성능·보안 검증의 필요 수준
- 고위험 변경 경계와 아키텍처 불변 조건
- 규제·컴플라이언스 요건과 데이터·프라이버시 정책
- 안티골 — 기술적으로 가능해도 하지 않을 것

## 산출물 상태

- `초안`: LLM이 분석·답변을 근거로 작성했으나 사용자 검토 전
- `확정`: 사용자가 확인한 프로젝트 사실·결정
- `미확정`: 결정 또는 검증이 필요한 항목. 임의로 채우지 않는다.

# Improvement Candidate: 검증-증거-자동-기록

- 상태: approved
- 생성: 2026-10-21

## 문제

검증 명령은 실제로 실행되지만 실행 시각·종료 코드·소스 지문·결과를 Exec Plan 완료 기록에 사람이 다시 옮겨 적어야 한다. 이 기록 마찰 때문에 검증을 통과한 작업도 AC 판정·완료 기록 누락으로 종결되지 않을 수 있다.

## 근거

work-status는 현재 활성 계획 20건 중 완료 기록·리뷰·AC 판정이 누락된 계획을 다수 보고한다. 현행 verify-plan은 검증을 실행한 뒤 계획에 증거를 기록하라고 안내할 뿐 자동 기록하지 않는다.

## 제안

- 활성 Exec Plan을 대상으로 검증을 실행하고, 실행 시각·명령·종료 코드·Git 기반 소스 상태 식별자·안전한 결과 요약을 같은 계획에 자동 추가하는 전용 Node 명령을 만든다.
- 기본 `verify-plan`의 읽기 전용 동작은 유지한다. 자동 기록 명령은 AC 판정·리뷰 판정·사람 완료 승인을 변경하지 않는다.
- 기록 명령·계약·도구 어댑터·배포 자산·회귀를 함께 추가해 설치 프로젝트에서도 같은 증거 기록 흐름을 쓴다.

## 영향 범위와 위험

- 영향 파일: 검증 증거 기록 Node 명령·CLI·shim·runtime asset 목록·Verify 계약·완료 기록 스키마·도구 어댑터·회귀 테스트.
- 위험: 실행 출력을 그대로 기록하면 민감정보가 남을 수 있고, 계획 파일 자체 변경을 소스 변경으로 오해하면 증거가 즉시 무효화될 수 있다. 전체 출력 저장 금지와 계획 파일 제외 소스 상태 식별 규칙이 필요하다.

# Improvement Candidate: E2E 도구 부재 시 승인형 프로필 제안·구성

- 상태: approved
- 생성: 2026-10-22
- 출처 실행 계획: docs/exec-plans/active/2026-10-22-095800-exam-login-page.md

## 문제

브라우저 사용자 흐름을 포함한 기능의 Exec Plan이 자동 Browser E2E를 필요로 해도 공통 프레임워크는 실행 계약만 제공하며 프로젝트별 도구·설정 생성 경로가 없다. 도구 설치를 하지 않으면 수동 UAT 또는 미검증 보류라는 판단은 가능하지만, 에이전트가 승인된 범위 안에서 일관되게 도구 설치를 제안·구성할 표준 절차가 없다.

## 근거

2026-10-22 exam/login 계획은 브라우저 UI AC 때문에 E2E가 필요하지만 .ai-dev-standard/e2e.json과 Playwright/Cypress가 없어 수동 Browser UAT로 지정됐다. 논의 결과 자동 E2E가 장기 회귀에 적합한 경우에는 사용자 승인 후에만 도구·브라우저·설정을 추가해야 하며, 거부 시 수동 UAT·AC 범위 조정·미검증 보류의 대안을 명확히 해야 한다.

## 제안

- Plan 계약에 `자동 E2E 준비 상태` 판정을 추가한다. Browser E2E가 AC에 필요하지만 실행 설정이 없으면, 에이전트는 자동 설치하지 않고 선택한 도구, 추가 의존성·브라우저 다운로드·CI 영향, 대상 AC, 수동 UAT 대안을 포함한 설치 제안을 낸다.
- 사용자가 Exec Plan을 승인한 경우에만 프로젝트별 E2E 프로필 구성 명령을 실행한다. 프로필은 최소 `Node API/System E2E`, `Playwright Browser E2E`, `Cypress Browser E2E`를 구분하고, 기존 프로젝트의 도구가 있으면 그것을 우선 재사용한다.
- 도구 설치 제안을 거부한 경우에는 수동 Browser UAT, AC 범위 조정, 또는 미검증 보류 중 승인된 대안을 Plan에 기록한다. UI AC가 남아 있고 수동 UAT 증거도 없으면 READY_FOR_REVIEW을 허용하지 않는다.
- 자동 E2E 실행은 기존 `.ai-dev-standard/e2e.json`의 command/args 계약을 계속 사용해 도구 중립성을 유지한다.

## 영향 범위와 위험

- 영향 파일: `docs/testing-policy.md`, `docs/skill-contracts/standard-plan.md`, `docs/skill-contracts/standard-implement.md`, E2E 설정/구성 명령과 그 회귀 테스트, 필요 시 온보딩 문서
- 위험: Playwright/Cypress 설치와 브라우저 다운로드는 네트워크·디스크·OS 의존성이 있으며 기존 패키지 관리자와 CI에 영향을 준다. 따라서 명시적 Plan 승인, 기존 도구 우선, 실패 시 부분 설치 상태 보고, 비대화형 자동 설치 금지가 필요하다.

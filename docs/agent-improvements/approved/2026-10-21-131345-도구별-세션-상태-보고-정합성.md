## 문제

새 세션 작업 상태 자동 보고 계약을 적용했지만 Claude는 work-status를 실행·보고하지 않았고, Codex는 work-status 결과의 진행 중 상태를 승인 대기로 오해해 사용자에게 부정확하게 보고했다.

## 근거

동일 프로젝트 경로에서 새 Claude·OpenCode·Codex 세션으로 'hi'를 입력해 확인했다. OpenCode는 상태를 정확히 보고했으나 Claude는 Preflight WARNING만 보고했고, Codex는 명령 실행 후 승인 대기 0건을 여러 승인 대기처럼 표현했다.

## 제안

- `CLAUDE.md`와 Claude의 세션 Preflight 어댑터에 공통 workflow의 `work-status` 실행·사용자 상태 보고 의무를 명시한다.
- 모든 도구 어댑터가 상태 보고 시 `work-status`의 분류를 임의 해석하지 않고, 활성 작업·전환 누락·승인 대기·최근 완료·Git 변경을 정확한 건수 또는 `없음`으로 보고하도록 공통 계약을 보강한다.
- 실제 새 세션에서 Claude·OpenCode·Codex를 대상으로 같은 시작 시나리오를 재검증한다.

## 영향 범위와 위험

- 영향 파일: `CLAUDE.md`, `.claude/skills/project-preflight/SKILL.md`, 필요 시 `AGENTS.md`, `docs/development-workflow.md`, 도구별 어댑터 회귀 문서 또는 테스트.
- 위험: 도구별 시작 Hook·지침 로딩 방식이 달라 단순 문서 참조만으로는 실행을 보장하지 못할 수 있다. 실제 도구 세션 재검증이 필요하다.

# 코딩 표준

> 모든 AI 도구와 개발자가 따르는 코드 작성 규칙.
> 이 문서와 각 언어 린터 설정이 충돌하면 린터 설정을 우선하고 이 문서를 갱신한다.

## 1. 공통 원칙

1. **기존 구조와 컨벤션 우선** — 주변 코드 → 설정 파일 → 테스트 순으로 확인 후 작성
2. **최소 diff** — 요청된 변경만. 리팩터링·포맷 변경은 별도 태스크
3. **원본 스타일 유지** — 따옴표, 들여쓰기, 함수 시그니처 줄바꿈 등 기존 방식 그대로
4. **하드코딩 금지 원칙** — 특정 사례만 통과시키는 분기보다 근본 원인 해결
5. **불필요한 의존성 추가 금지**

## 2. 네이밍

| 대상 | 규칙 | 예시 |
|---|---|---|
| 변수/함수 (JS/TS) | camelCase | `getUserById` |
| 컴포넌트/클래스 | PascalCase | `UserList` |
| Python 변수/함수 | snake_case | `get_user_by_id` |
| 파일명 | kebab-case 권장 | `user-service.ts` |
| 테스트 파일 | 대상 파일명 + `.test` | `user-service.test.ts` |
| 상수 | SCREAMING_SNAKE | `MAX_RETRY` |

## 3. 언어별 기본 (프로젝트 적용 시 조정)

- **JS/TS**: 2칸 들여쓰기, 세미콜론, ESLint 준수
- **Python**: PEP8, 4칸 들여쓰기
- **주석**: 프로젝트 기본 언어(한국어)로 "왜"를 설명.
  코드가 말하는 "무엇"의 반복 금지

## 4. 커밋 메시지

형식: `<type>: <한글 요약>`

| type | 용도 |
|---|---|
| feat | 기능 추가 |
| fix | 버그 수정 |
| refactor | 리팩터링 (동작 불변) |
| test | 테스트 추가/수정 |
| docs | 문서 |
| chore | 빌드/설정/도구 |

예시: `fix: 토큰 만료 시 재발급 누락 수정`

## 5. 보안 기본

- API key·토큰·비밀번호·`.env` 내용을 코드·로그·커밋에 두지 않는다
- 민감정보가 diff에 발견되면 원문 재출력 금지, 마스킹
- 인증/인가·마이그레이션·인프라 변경은 고위험 — 완료 기록에
  영향 범위를 반드시 명시

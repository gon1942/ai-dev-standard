# Product Spec: 배포 템플릿 정리

- 상태: approved
- 유형: 신규 기능  (신규 기능 | 수정 | 버그 | 리팩터링 | 성능)
- 깊이: 설계 필요  (단순 | 일반 | 설계 필요)
- 생성: 2026-10-20
- 사용자 요청: GitHub에 저장·배포하기 전에 프레임워크 원본의 개발 이력과 로컬 생성물을 보존하면서, 신규 프로젝트에 안전하게 제공할 깨끗한 배포 템플릿을 생성하도록 정리해줘.

## 문제·목표

- 문제: 현재 저장소는 프레임워크 개발 원본이므로 자체 Product Spec·활성 Exec Plan·원본 전용 회귀 테스트·세션 보고서가 함께 존재한다. 이를 그대로 GitHub Template로 사용하면 신규 프로젝트에 원본 이력과 환경별 상태가 복제된다.
- 영향: 신규 사용자에게 불필요한 문서와 잘못된 `active` 검증 상태가 전달될 수 있고, CLI가 생겨도 원본과 배포 자산의 경계가 불명확해진다.
- 목표: 원본 이력은 보존하면서, 명시된 자산만 포함한 `template` 모드의 신규 프로젝트용 배포 디렉터리를 재현 가능하게 만든다.
- 성공 기준: 배포 빌드가 깨끗한 출력 디렉터리를 만들고, 출력은 골격 검사를 통과하며, 원본 이력·로컬 캐시·원본 전용 테스트를 포함하지 않는다.

## 대안과 선택 사유 (구현 방식이 여럿 가능한 경우만 작성, 없으면 이 섹션을 지운다)

| 안 | 장점 | 단점 | 선택 여부·사유 |
|---|---|---|---|
| 현재 원본 저장소를 GitHub Template로 직접 사용 | 별도 빌드가 없다 | 원본 작업 이력·`active` 설정·생성 보고서가 복제된다 | 미선택 — 신규 프로젝트에 부적합하다. |
| 원본에서 배포 디렉터리를 빌드 | 원본 이력과 배포 자산을 분리하고, 향후 CLI도 같은 출력물을 사용할 수 있다 | 빌드·회귀 테스트를 유지해야 한다 | 선택 — 소스와 배포물의 경계를 기계적으로 검증할 수 있다. |

## 확인 필요 사항

- GitHub Template용 별도 원격 저장소 생성과 npm/CLI 배포는 후속 작업으로 둔다.
- 현재 활성 Exec Plan의 사람 리뷰·완료 이동은 이 작업에서 처리하지 않는다.

## 확정 요구사항

- 프레임워크 원본의 Product Spec·Exec Plan·원본 전용 회귀 테스트는 삭제하지 않는다.
- 배포 템플릿은 `template` 모드의 `.ai-dev-standard.env`를 포함한다.
- 배포 템플릿은 공통 문서, 스킬 계약, 런타임 스크립트, 도구별 어댑터, 빈 공식 기록 디렉터리를 포함한다.
- 세션 캐시, 생성된 Preflight 보고서, OpenCode 로컬 의존성, 원본 전용 회귀 테스트, 원본 작업 이력은 배포 템플릿에서 제외한다.
- 빌드 결과와 제외 규칙은 자동 테스트로 검증한다.

## 완료 조건 (Acceptance Criteria)

| ID | 완료 조건 | 기대 결과 |
|---|---|---|
| AC-01 | 배포 템플릿 빌드 | 지정한 빈 출력 경로에 재현 가능한 템플릿이 생성된다. |
| AC-02 | 배포 골격 유효성 | 생성된 템플릿이 `check-framework.sh`를 통과하고 `.ai-dev-standard.env`는 `template` 모드다. |
| AC-03 | 원본·로컬 산출물 제외 | Product Spec 이력, 활성 Exec Plan 이력, Preflight 보고서, 세션 캐시, `.opencode/node_modules`, 원본 전용 회귀 테스트가 출력에 없다. |
| AC-04 | 생성 디렉터리 보존 | 새 프로젝트가 공식 기록을 시작할 수 있도록 빈 `product-specs`, `exec-plans`, `design-docs`, `agent-improvements` 영역과 인덱스가 있다. |
| AC-05 | 회귀 보호 | 빌드·제외 규칙·골격 검사를 자동 테스트로 다시 실행할 수 있다. |
| AC-06 | 배포 경계 문서화 | 원본 저장소·배포 템플릿·향후 CLI의 책임과 사용 방법이 문서에 명확히 설명된다. |

## 범위

- 포함: 배포 템플릿 빌드 스크립트와 회귀 테스트, 템플릿에 필요한 최소 문서·기록 디렉터리 구성, volatile 생성물 ignore 정책, 배포 절차 문서화.
- 비목표(제외): 이번 작업에서 의도적으로 하지 않는 것: GitHub 원격 저장소·Release·Template 저장소 생성, npm 패키지 또는 CLI 배포, 기존 활성 계획의 리뷰·완료 이동, `.opencode/node_modules`의 물리적 삭제, CI/CD·의존성·전역 Hook 설정 변경.

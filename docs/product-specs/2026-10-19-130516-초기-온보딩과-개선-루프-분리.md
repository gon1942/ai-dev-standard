# Product Spec: 초기 온보딩과 개선 루프 분리

- 상태: approved
- 생성: 2026-10-19
- 사용자 요청: 공통 프레임워크는 최초 적용 또는 구조 이상 시에만 에이전트가 필수 구조를 검사·분석하고, 일반 작업 완료 후에는 개선 후보를 제안해 사람 승인 뒤 별도 작업으로 공통 파일을 업데이트하도록 개선해줘

## 확인 필요 사항

- 일반 기능 요청마다 전체 온보딩을 반복하지 않는다.

## 확정 요구사항

- 에이전트는 프레임워크 최초 적용, 필수 구조 누락·손상 발견, 사용자의 재분석 요청에서만 온보딩을 수행한다.
- 온보딩은 구조 검사·읽기 전용 분석·필요한 기본 골격 생성으로 구성한다.
- 일반 작업은 제품 명세·실행 계획 흐름을 바로 사용한다.
- 작업 완료 후 반복 문제·검증 누락·도구 공백이 있을 때만 개선 후보를 제안한다.
- 사람 승인 후 개선 후보는 별도 제품 명세·실행 계획으로 구현하고 검증한다.

## 완료 조건 (Acceptance Criteria)

| ID | 완료 조건 | 기대 결과 |
|---|---|---|
| AC-01 | 온보딩 트리거 | 문서·도구 지침에 최초 적용·구조 이상·명시 요청만 온보딩으로 명시된다 |
| AC-02 | 일반 작업 흐름 | 일반 기능 요청은 온보딩 반복 없이 제품 명세·실행 계획으로 시작한다 |
| AC-03 | 개선 제안 | 완료 후 필요한 경우에만 개선 후보를 제안하고, 승인 전 공통 파일을 수정하지 않는다 |
| AC-04 | 승인 후 반영 | 승인 후보는 별도 명세·계획·검증을 거쳐 파일을 갱신하도록 명시된다 |

## 범위

- 포함: 워크플로, 온보딩 문서, AGENTS, 도구별 구현 스킬, 개선 후보 정책.
- 제외: 자동 AGENTS.md 수정, 승인 없는 공통 파일 변경, 신규 의존성 설치.

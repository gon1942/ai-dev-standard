# Product Spec: 프레임워크 실행 자산·회귀 검증 완결성

- 상태: approved
- 유형: 수정  (신규 기능 | 수정 | 버그 | 리팩터링 | 성능)
- 깊이: 설계 필요  (단순 | 일반 | 설계 필요)
- 생성: 2026-10-20
- 사용자 요청: 공통 프레임워크를 새·기존 프로젝트에 적용했을 때 Plan부터 완료 처리까지 필요한 실행 자산이 빠짐없이 제공되고, 프레임워크 자체의 Preflight·Plan 템플릿·계획 검증 회귀 테스트를 단일 진입점에서 실행할 수 있도록 개선해줘.

## 문제·목표

- 문제: 적용 대상 프로젝트의 전체 작업 흐름은 `review.sh`와 `complete-exec-plan.sh`를 필요로 하지만, 현재 골격 생성·검사·적용 목록 사이에 실행 자산 누락과 중복 목록이 있다. 또한 Preflight·계획 템플릿·계획 검증 회귀 테스트는 개별 스크립트로만 존재해 한 번에 실행하는 프레임워크 전용 진입점이 없다.
- 영향: 새·기존 프로젝트에 프레임워크를 적용한 뒤 Review 또는 완료 이동 단계에서 필요한 스크립트가 없을 수 있고, 이후 변경이 Plan·Preflight 게이트를 약화시켜도 표준 검증 흐름에서 발견되지 않을 수 있다.
- 목표: 사람용 적용 계약과 기계용 실행 자산 목록을 정합화하고, 새로 초기화한 프로젝트가 전체 Plan → Verify → Review → 완료 이동 경로에 필요한 실행 자산을 갖도록 한다. 프레임워크 저장소에서는 핵심 회귀 테스트를 한 명령으로 실행할 수 있게 한다.
- 성공 기준: 새 대상 프로젝트의 골격 생성·검사가 같은 필수 실행 자산을 기준으로 동작하고, 프레임워크 전용 회귀 테스트가 Preflight·Plan 검증·Plan 템플릿 시나리오를 모두 실행한다.

## 대안과 선택 사유 (구현 방식이 여럿 가능한 경우만 작성, 없으면 이 섹션을 지운다)

| 안 | 장점 | 단점 | 선택 여부·사유 |
|---|---|---|---|
| 각 스크립트의 목록을 개별 보정 | 변경량이 작고 즉시 적용 가능 | 다음 자산 추가 때 목록이 다시 어긋날 수 있음 | 미선택 — 현재 누락은 중복 목록 드리프트가 원인임 |
| 기계용 실행 자산 목록을 하나로 두고 bootstrap·check·회귀 테스트가 재사용 | 누락·중복을 한 곳에서 관리하고 새 자산 추가 시 회귀 검사 가능 | 작은 공통 목록 파일과 호출부 정리가 필요 | 선택 — 사람용 `framework-manifest.md`는 정책 설명, 기계용 목록은 실행 기준으로 역할을 분리 |

## 확인 필요 사항

- 이 저장소의 실제 검증 구성을 승인해 `AI_DEV_STANDARD_MODE=active`로 전환할지 결정이 필요하다. 현재 Session Preflight는 `template` 모드이므로 Plan만 허용하고 코드·스크립트 변경은 차단한다.
- active 전환 시 프레임워크 전용 회귀 테스트를 어떤 표준 명령으로 연결할지(예: `scripts/test-framework.sh`)를 실행 계획에서 확정해야 한다.

## 확정 요구사항

- 사람용 적용 계약(`docs/framework-manifest.md`)과 기계용 실행 자산 목록의 역할을 분리하되, 서로 모순되지 않게 갱신한다.
- 골격 생성과 골격 검사는 같은 런타임 필수 자산 집합을 사용한다.
- Review와 사람 승인 후 완료 이동에 필요한 실행 스크립트도 적용 대상에 안전하게 복사·검사한다.
- 프레임워크 자체 회귀 테스트는 대상 프로젝트의 일반 `scripts/verify.sh`와 분리한다. 대상 프로젝트의 lint·typecheck·제품 테스트 명령을 프레임워크 자체 테스트로 대체하지 않는다.
- 기존 파일을 덮어쓰지 않는 bootstrap 원칙과 기존 프로젝트의 승인 경계를 유지한다.
- CI/CD, 외부 프로젝트의 소스·의존성·검증 명령은 이 작업에서 변경하지 않는다.

## 완료 조건 (Acceptance Criteria)

| ID | 완료 조건 | 기대 결과 |
|---|---|---|
| AC-01 | 실행 자산 기준 정합성 | 골격 생성·골격 검사·적용 계약이 Plan부터 완료 이동까지 필요한 런타임 자산을 일관되게 정의한다. |
| AC-02 | 새 대상 프로젝트의 완전한 골격 | 임시 대상 프로젝트를 초기화하면 Review와 완료 이동을 포함한 필수 실행 스크립트가 존재하고 골격 검사를 통과한다. |
| AC-03 | 프레임워크 회귀 테스트 단일 진입점 | Preflight·Plan 검증·Plan 템플릿 회귀 시나리오를 한 명령으로 실행해 모두 PASS 또는 실패 원인을 반환한다. |
| AC-04 | 대상 프로젝트 검증과의 분리 | 대상 프로젝트의 `verify.sh`는 프레임워크 저장소 전용 테스트를 강제로 실행하지 않으며, 기존 프로젝트별 검증 책임을 유지한다. |
| AC-05 | 기존 동작 회귀 없음 | 기존 Preflight·bootstrap·validate-plan·템플릿 회귀 테스트가 계속 PASS하고, 기존 파일을 덮어쓰지 않는다. |

## 범위

- 포함: 실행 자산 목록·골격 생성·골격 검사·적용 계약의 정합화, 프레임워크 전용 회귀 테스트 진입점, 관련 자동 테스트와 문서 갱신.
- 비목표(제외): 이번 작업에서 의도적으로 하지 않는 것: Plan Traceability v2, 외부 프로젝트 소스·의존성·CI/CD 변경, 실제 사용자 프로젝트의 active 전환, Review 에이전트 자동 호출, JSON 검증 증거 스키마 도입.

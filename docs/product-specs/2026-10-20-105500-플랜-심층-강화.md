# Product Spec: 플랜-심층-강화

- 상태: approved
- 유형: 수정
- 깊이: 일반
- 생성: 2026-10-20
- 사용자 요청: 깊이 분류·구현 작업 표·Self-Review·명세 설계 섹션·테스트 경계·그릴링 기법 흡수

## 문제·목표

- 문제: Plan 단계는 승인·기록·게이트는 강하지만 설계 탐색·명세 품질·실행 계획의 구체성이 약하다 — 구현 계획이 자유 서술이라 구현자가 파일·명령을 추정한다.
- 영향: 계획 승인이 "다른 에이전트가 그대로 구현할 수 있는 실행 계약"이 되지 못하고, 모든 작업에 같은 깊이를 강제해 단순 수정이 느려진다.
- 목표: 깊이 3분류를 루트로 정의하고, 그 깊이에 따라 명세 섹션·구현 작업 표·Self-Review 범위가 결정되는 구조를 만든다.

## 비목표

- 이번 작업에서 하지 않는 것: validate-plan 게이트 경화(작업 표 필수·AC↔작업 연결 검사는 후속 관찰 후), 이슈 트래커 발행·자동 커밋·Superpowers 전용 실행 방식 이식, 어댑터 스킬 변경.

| ID | 완료 조건 | 기대 결과 |
|---|---|---|
| AC-01 | 깊이 분류 정의 | 계약에 단순/일반/설계 3단·판정 주체·깊이별 산출물 규칙 존재 |
| AC-02 | 구현 작업 표 | exec-plan 템플릿에 6열 표(순서/대상/내용·인터페이스/검증 명령/기대 증거/AC)와 `조사 필요` 마커·조사 안전 범위 규칙 존재 |
| AC-03 | Self-Review 액션 | 계약에 5질문 점검 액션 존재 |
| AC-04 | 명세 설계 섹션 | spec 템플릿에 `깊이` 필드·문제·목표·비목표·대안 표 존재, 문제·목표/재현 조건 분리 기준 명시 |
| AC-05 | 그릴링 기법·테스트 경계·깊이 요약 | workflow §3.1에 질문 기법, testing-policy에 테스트 경계 원본, workflow §4에 깊이별 절차 요약 존재 |

| AC-07 | 회귀 없음 | 기존 계획 7건 validate PASS, test-validate-plan.sh 7분기 PASS, 신규 템플릿 생성 실측 통과 |

## 구현 계획

- 목적: 공통 프레임워크를 적용한 대상이 Plan부터 Review·사람 승인 후 완료 이동까지 필요한 실행 자산을 빠짐없이 받고, 프레임워크 자체의 핵심 회귀 테스트를 한 명령으로 실행하게 한다.
- 범위: 실행 자산의 기계용 목록 추가, bootstrap·check·적용 보고서·Preflight의 목록 재사용, runtime 누락 보완, 프레임워크 전용 회귀 테스트 진입점과 이 저장소의 active 검증 연결, 관련 계약 문서·테스트 갱신.
- 제외: Plan Traceability v2, 외부 프로젝트 코드·의존성·CI/CD 변경, 대상 프로젝트의 사용자 정의 검증 명령 변경, Review 에이전트 자동 호출, JSON 증거 스키마.
- 영향 파일 (예상): docs/framework-manifest.md, docs/framework-runtime-assets.tsv(신규), docs/project-preflight.md, docs/session-preflight.md, README.md, .ai-dev-standard.env, scripts/bootstrap-framework.sh, scripts/check-framework.sh, scripts/plan-framework-apply.sh, scripts/project-preflight.sh, scripts/test.sh, scripts/test-framework.sh(신규), scripts/test-framework-assets.sh(신규), scripts/test-project-preflight.sh.

## 회귀 검증 대상

- `scripts/test-project-preflight.sh`: Node/Python/손상 설정/반복 실행/세션 캐시 회귀
- `scripts/test-validate-plan.sh`: 승인·AC 검증 계획·버그 재현 게이트 7분기 회귀
- `scripts/test-plan-templates.sh`: 명세·실행 계획 템플릿 섹션·6열 작업 표 회귀
- 기존 bootstrap의 “없는 파일만 생성, 기존 파일 보존” 원칙
- 일반 대상 프로젝트의 `scripts/test.sh` Node·pytest 감지 동작

## 실패 시 대응

- 자산 목록과 기존 대상 골격이 충돌하면 대상 파일을 덮어쓰지 않고, 목록·Manifest·검사 정책을 다시 Plan 단계에서 조정한다.
- active 모드에서 프레임워크 테스트가 실행되지 않으면 active 전환을 되돌리고, 감지 규칙과 실제 테스트 진입점을 먼저 수정·재검증한다.
- 일반 대상 프로젝트의 test runner가 프레임워크 원본 전용 테스트를 실행하면 조건을 좁히고 임시 대상 회귀 테스트를 추가한 뒤 다시 검증한다.

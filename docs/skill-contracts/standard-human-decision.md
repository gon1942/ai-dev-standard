# Standard Human Decision Gate Contract

사람의 결정이 필요한 게이트에서 모든 도구가 따르는 공통 계약이다. 이 계약은 사람의
승인 권한을 자동화하지 않으며, 선택형 UI는 호스트 앱이 지원할 때만 사용한다.

## 공통 규칙

- 에이전트는 게이트의 목적, 현재 상태, 가능한 선택과 각 선택의 다음 상태를 분명히 제시한다.
- 호스트가 선택형 입력을 지원하면 선택형 UI를 우선 사용한다. 지원하지 않으면 같은 선택을
  텍스트 응답으로 받는다.
- 명시적인 사람 결정 없이는 승인·완료 상태로 전이하지 않는다.
- 결정과 결정자는 해당 공식 기록(Product Spec, Exec Plan, 후보 파일)에 남긴다.

## 표준 게이트

| 게이트 | 선택 | 다음 상태·행동 |
|---|---|---|
| Product Spec | 승인 / 수정 요청 / 보류 | `approved` 전환 / draft 보완 / 현 상태 유지 |
| Exec Plan | 승인 / 수정 요청 / 보류 | `승인: approved` / 계획 보완 / pending 유지 |
| 기존 프로젝트 적용 | 승인 / 범위 수정 / 거부 | 승인 범위 반영 / 적용 계획 수정 / 변경 없음 |
| 개선 후보 | 승인 / 기각 / 보류 | `approved` / `rejected` / candidate 유지 |
| 변경 사항 검토 | 완료 처리 / 추가 개선 / 보류 | `done`과 completed 이동 / Implement·Verify 복귀 또는 새 작업 / 검토 상태 유지 |

## 도구별 입력

- 선택형 UI 지원 도구: 위 선택지를 버튼·선택창 등 호스트가 제공하는 방식으로 제시한다.
- UI 미지원 도구: 사람이 `승인`, `수정 요청`, `보류`, `완료 처리`, `추가 개선`, `기각`처럼
  해당 게이트의 선택을 텍스트로 답할 수 있게 한다.
- 모호한 답변은 승인으로 추정하지 않고, 필요한 결정을 한 문장으로 다시 확인한다.

## 사용자 보고 형식

변경 사항 검토 결과는 다음 순서로 제시한다. 내부의 구현자와 분리된 리뷰 원칙은
`standard-review` 계약에 유지하며, 사용자 보고에는 이 용어를 노출하지 않는다.

```text
검토 결정 필요

변경 사항 검토: PASS / 주의 필요 / 수정 필요
- 자동 검증: ...
- 명세 충족: ...
- 남은 위험: ...

사용자 결정
1. 완료 처리
2. 개선 요청
3. 보류
```

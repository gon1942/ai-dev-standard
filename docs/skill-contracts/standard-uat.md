# Standard UAT Contract

- 성격: 선택 계약 — Plan의 검증 계획에서 해당 AC의 검증 방법이 `UAT`로 지정된
  경우에만 적용한다. 전 작업의 필수 게이트가 아니다.
- 대상: 자동 테스트만으로 증명하기 어려운 사용자가 관찰 가능한 AC
  (화면 동작, API 실사용 흐름, 사용자 시나리오 등).

## Entry conditions

- Implement가 완료됐고 검증 계획에 `UAT`로 지정된 AC가 있다.

## Required actions

- 지정 AC의 사용자 시나리오를 추출해 수행 절차와 기대 결과를 정리한다.
- 시나리오를 실제로 실행한다 (브라우저 실측, API 호출 등 사용 가능한 수단).
- 판정:
  - **PASS** — 기대 결과와 일치. 수행 절차와 관찰 결과를 증거로 기록한다.
  - **FAIL** — 원인을 분석하고 수정 계획을 세운 뒤 수정하고 재검증한다.
    재시도 전 원인 분석이 선행되어야 한다 (루프).
- **증거 위치 (필수)**: 최종 판정과 증거는 반드시 Exec Plan의 완료 기록·AC 판정 표에
  기록한다. 임시 메모·대화 기록으로만 끝내지 않는다 — 수렴 판정과 리뷰는 Exec Plan
  파일을 직접 검사하므로, 공식 기록에 없는 UAT 결과는 승인 근거에서 누락된다.
- 진행 정보(시나리오 2/4 완료, 재개 지점 등)도 Exec Plan의 검증 계획 아래에 남겨
  세션이 끊겨도 이어서 진행할 수 있게 한다.
- 자동 테스트로 입증되는 항목과 사람 판단이 필요한 항목을 구분해 기록한다.
- 검증 계약 버전 2의 수동 Browser UAT가 E2E 판정으로 지정됐으면 `## E2E 검증 증거`에
  `### 수동 UAT <식별자>`, `- 실행 일시:`, `- 관찰 결과:`, `- 판정: PASS|FAIL`을 모두 기록한다.
  브라우저·권한·외부 환경이 없어 수행하지 못했으면 PASS를 쓰지 않고 미검증 사유를 남긴다.

## Outputs

- UAT 시나리오별 판정과 관찰 증거 (Exec Plan에 기록)

## Exit conditions / next stage

- 지정 AC가 모두 PASS면 standard-verify의 나머지 절차와 함께 Review로 진행한다.
- FAIL 루프가 수렴하지 않으면 사람에게 상황·근거·남은 위험을 보고하고 판단을 기다린다.
